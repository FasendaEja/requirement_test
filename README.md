# Тестирование требований с помощью ИИ

Утилита на Python: рекурсивно читает файлы с требованиями из папки `input/`
(и всех вложенных подпапок), отправляет их содержимое в ИИ (OpenAI-совместимый
API, модель `qwen3.8`) для статического тестирования требований и сохраняет
полученный результат в файл `тестирование требований__<дата_время>.md`.

## Структура проекта

```
├── main.py            # утилита (точка входа)
├── prompt.txt         # промт для ИИ (редактируется пользователем)
├── .env               # ВСЕ параметры утилиты (токен, путь до API, пути, модель...)
├── .env.example       # шаблон настроек
├── requirements.txt   # зависимости
├── input/             # файлы с требованиями (примеры во всех форматах)
│   ├── sub/           # пример вложенной папки
└── output/            # сюда сохраняются результаты
```

Поддерживаемые форматы входных файлов: **doc, docx, md, pdf, txt, xlsx, xml, json**
(список настраивается через `SUPPORTED_EXTENSIONS` в `.env`).

## Установка и запуск

```bash
pip install -r requirements.txt
# 1. Положить файлы с требований в input/ (можно во вложенные папки)
# 2. Отредактировать prompt.txt при необходимости
# 3. В .env указать:
#      OPENAI_API_KEY  — токен для доступа к ИИ
#      OPENAI_BASE_URL — путь до API ИИ
python main.py
```

Результат появится в `output/` с именем вида
`тестирование требований__2026-10-29_14-30-00.md`.

## Порядок обработки (важно)

Запрос к ИИ выполняется **синхронно** (`stream=False`): утилита дожидается
полного ответа модели, печатает `[ОТВЕТ ПОЛУЧЕН]`, и только после этого
начинается обработка и сохранение результата. При ошибках сети/API
предусмотрены ретраи (`MAX_RETRIES`, `RETRY_DELAY`).

## Параметры (.env)

| Параметр | Описание | Значение по умолчанию |
|---|---|---|
| `OPENAI_API_KEY` | Токен для доступа к ИИ | — |
| `OPENAI_BASE_URL` | Путь до API ИИ | `https://api.openai.com/v1` |
| `MODEL` | Модель ИИ | `qwen3.8` |
| `TEMPERATURE` | Температура генерации | `0.1` |
| `MAX_TOKENS` | Максимум токенов ответа | `200000` |
| `TIMEOUT` | Таймаут запроса, сек | `600` |
| `MAX_RETRIES` | Число повторов при ошибках | `3` |
| `RETRY_DELAY` | Пауза между повторами, сек | `5` |
| `SYSTEM_PROMPT` | Системная роль для модели | аналитик требований |
| `INPUT_DIR` | Папка с файлами требований (рекурсивно) | `input` |
| `PROMPT_FILE` | Файл с промтом | `prompt.txt` |
| `OUTPUT_DIR` | Папка для результатов | `output` |
| `SUPPORTED_EXTENSIONS` | Расширения входных файлов | `doc,docx,md,pdf,txt,xlsx,xml,json` |
| `RESULT_PREFIX` | Префикс имени файла результата | `тестирование требований__` |
| `OUTPUT_EXTENSION` | Расширение файла результата | `.md` |
| `TIMESTAMP_FORMAT` | Формат даты-времени в имени | `%Y-%m-%d_%H-%M-%S` |
| `MAX_FILE_CHARS` | Лимит символов на файл (0 = без лимита) | `0` |

Относительные пути в `.env` разрешаются относительно папки проекта, поэтому
запускать утилиту можно из любой директории.

## Примечания

- Для `.doc` утилита пытается использовать `antiword` или `libreoffice`
  (если установлены); иначе выполняет эвристическое извлечение текста.
- Примеры файлов в `input/` можно заменить своими — формат структуры сохраняется.
